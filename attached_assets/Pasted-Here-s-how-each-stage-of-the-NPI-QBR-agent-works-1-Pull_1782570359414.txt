Here's how each stage of the NPI QBR agent works:
1. Pull Jira tickets and changelog — The agent queries two things from Jira: the roadmap board filtered to customer-visible labeled tickets, and the changelog for shipped items from the last 90 days. Crucially, it also pulls any linked customer-request tickets on each item — this tells the agent which features real accounts asked for, which drives prioritization in the next step.
2. Segment and prioritize by NPI theme — Raw Jira output is full of engineering language and internal labels. Claude reads every ticket and groups them into 3–5 customer-meaningful themes (reporting, access controls, integrations, etc.). Within each theme, items are ranked by how many linked customer requests they have — so the QBR deck leads with what matters most to the account in the room, not what happened to ship last.
3. Write customer-friendly copy — This is the core of the NPI self-serve bet. Engineering descriptions like "Refactor RBAC middleware to support multi-tenant ACL scoping" become "Control exactly who sees which dashboards — no more sharing workarounds." The prompt enforces a 25-word cap per bullet, bans jargon, and applies different tense frames for shipped vs. coming soon vs. horizon items.
4. Build the slide deck — Customer copy is injected into a PowerPoint template pulled from Google Drive. The agent generates a title slide, one "what we shipped" slide per theme, a visual timeline, and a what's next slide. All layout, fonts, colors, and logo placement come from the company template — the agent only touches content blocks.
5. Publish and notify — The finished deck uploads to a shared /QBR Assets/Q3 2026/ folder in Drive, and the agent posts a brief to #customer-success in Slack with a direct link. Run this on a quarterly cron and the folder is always current — reps never have to chase product or PM for slide content again.
The self-serve angle that makes this powerful: once this runs, customer-facing teams have accurate, customer-ready roadmap language without any manual translation from product. The knowledge gap that drives stuck@ tickets about "what's shipping and when" closes automatically.
